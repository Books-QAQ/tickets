## 2. 关键设计决定（写进代码注释，防止后人"优化"掉）

1. **`cache_lookup` 必须是图内节点，不是 Go 转发前短路**：短路的那一轮不进 checkpoint → 下一轮指代消解缺上下文。
2. **缓存命中仍要过 `verify`**：缓存省的是**检索+生成**，不是合规检查。命中直连 `finalize` 会让能力边界声明整段消失（本轮实测翻红 M1 回归）。配套把 `verify` 的声明注入做成**幂等**。
3. **记忆不能出现在 `new_initial_state` 里**：入口把它当输入传给 `ainvoke`，langgraph 视作一次 state 更新 → 写 `recent=[]` 等于每轮清空记忆。
4. **E11 改写必须机检**："改写结果"必须是短问句；模型吐答案/带引用/超长一律拒绝，**且拒绝后直接转人工**（空跑第二遍会把指代继承的分类覆盖掉）。
5. **确定性拒绝不计熔断**：闸门未确认（`penalty_semantics_unconfirmed`）是业务结论不是故障；计进去会让 `circuit_open` 污染坐席看到的判定原因。
6. **Go 是 SSE 出口，负责把协议规范化**：上游 CRLF → LF；**空行是帧分隔符，必须转发**。
7. **`stream` 契约必须显式**：SSE 是 opt-in（默认 JSON），调用方显式传 `stream:false`。

## 3. 实现期踩到的 9 个真问题（含根因与修法）

### P1 降级路径自己把服务打崩（panic）
`degradeToTicket` 写 `fmt.Sprintf(...)[:500]` —— 问题只有 84 字节时 `slice bounds out of range`，
**整个 Go 进程 panic**（本来只是"编排层不可用"）。修：`clampRunes()` 按 **rune** 截断。
教训：降级路径必须永不崩，所有截断走同一个函数。

### P2 `PYTHON_BASE_URL` 从未配置 → 每轮静默降级成工单
M2 的验收一直**直接打编排层**，所以"Go→编排层"这条路从没被跑过；配漏了的表现是"用户问什么都回工单号"。
修：① 驱动脚本显式传；② `BuildCSComponents` 启动时 `log.Error` 报警（静默降级是最坏失败类）。

### P3 stream 契约不一致（默认值事故）
编排层 `/ask` 的 `stream` 默认 **True**，Go 非流式分支不带该字段 → 拿到 SSE 正文 → JSON 解析失败 → 降级。
修：默认 False + Go 显式传 `false` + Go 侧解析失败时明确指出"返回 SSE 但期望 JSON"。

### P4 SSE 帧永远拼不起来（两处）
上游（sse-starlette）用 **CRLF**，帧分隔是 `\r\n\r\n`；且 Go 转发时**把空行 `continue` 掉了**。
→ 客户端按 `\n\n` 切帧永远切不开、只能等整轮结束才渲染。curl 看"有内容"，任何 SSE 解析器都读到空。
修：Go 出口 `TrimRight(line,"\r")` + **转发空行**（带 prevBlank 去重）；前端/验收脚本再做 `\r\n→\n` 双保险。

### P5 记忆每轮被清空
`new_initial_state()` 里写 `recent=[]/summary=""`，作为输入覆盖 checkpoint。修：删掉这两个键，并弃用 append-only 的 `history`（无上限撑大 checkpoint），生成 prompt 的上下文改由 `recent+summary` 现算。

### P6 E11 改写把答案当改写结果
mock/弱模型返回"抱歉，我暂时没有找到相关信息。"当"改写后的问题" → 第二遍分类作用于垃圾输入 → 又把指代继承的分类覆盖回 `other`。
修：`_valid_rewrite()` 机检（空/超长/带引用/答案话术/未改动全部拒绝）+ 被拒直接转人工（新增 `rewrite_failed` 标志与条件边）。

### P7 `clarify` 同超步双写 → `InvalidUpdateError`
`clarify` 既有 M2 留下的静态边 `→finalize`，又有 M3 的条件边 `→exec_tool|transfer`：
resume 时 `transfer` 与 `finalize` 在同一超步并行执行，两者都写 `answer` → 图报错。
修：删掉静态边。教训：**改条件边时必须清掉同源的静态边**。

### P8 缓存命中绕过合规检查
命中直连 `finalize` → `verify` 不跑 → 能力边界声明消失（**M1 回归因此翻红**：`候补购票怎么操作` 判"缺边界声明"）。
修：命中边改 `verify` + 带上缓存里的 `source_labels`（Go 的边界判定只依赖来源 chunk 的 capability）+ `verify` 注入幂等。

### P9 确定性拒绝被计入熔断 → 判定原因漂移
闸门关闭连续触发 3 次即熔断，之后同一工具返回的原因从 `penalty_semantics_unconfirmed` 漂成 `circuit_open`，
**坐席在工单里看到的判定原因失真**（M2 的 D1 用例因此翻红）。修：`deterministicUnavailable` 白名单不计熔断 + 单独计数 `tool_gate_closed_total`；新增单测锁死（连问 10 次 → `circuit_open=0`）。

### 附：`/healthz` 假健康信号
`checkpointer` 读的是构造参数（生产路径在 lifespan 里按 DSN 打开，构造参数恒 `None`）→ 一边连着 MySQL 一边自报 `"checkpointer": false`。修：读 `app.state`。
