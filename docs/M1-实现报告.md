## 2. 端到端验收结果（真实运行，非构造）

环境：MySQL 8.4.11 + Qdrant 1.19.1（容器）+ Go 服务（`LLM_PROVIDER=mock`、`EMBEDDING_PROVIDER=fake`）+ Python 编排层（uvicorn :8001）。

```
20 条问题：作答 13 / 转人工 7
Go 计数点：decision_generate_ok=12  decision_verify_ok=12  filter_relaxed_total=4
           below_threshold_total=5  answers_with_boundary_total=1
           boundary_violation_blocked_total=1  support_ticket_created_total=7
```

| M1 验收项 | 结果 |
|---|---|
| 分支行为正确（20 条覆盖 greet / 确定转人工 / 检索作答 / 无依据转人工） | ✅ 13 答 + 7 转（`deterministic=2`、`threshold=5`） |
| 无依据必转人工 | ✅ 「你们老板是谁」「今天天气」「会员积分」「联程票」全部转人工 |
| **边界声明覆盖率 100%** | ✅ 0 缺失（`waitlist` 类来源非 supported → 声明已注入） |
| **入口真实性 0 违规** | ✅ 交付答案中操作性措辞 0 条（1 次被拦截并剥除，计数 1） |
| 批量入库可断点续跑 | ✅ 二次入库 `skipped=5 embedded=0`（`content_hash` 游标生效） |
| 契约测试通过 | ✅ 鉴权 401/401/200；非流式与流式网关均通 |
| 游客检索不到 authenticated chunk | ⚠️ **未验**（当前内容样本里没有 `authenticated` 文档；过滤器代码路径已实现，待补样本） |

**一条已知局限（已归档，不算失败）**：「行李能带多少」在本环境下**被作答了**。原因是词面替身 embedding + 未标定的 BM25 门槛（3.0）过宽，词面部分重合即判为相关 —— 这正是 §7.5 警示的"字面替身模式下不允许把有结果即相关写死为 true"。换真实 embedding 并完成阈值标定后，该问题应交由阈值拦截或转人工。

## 3. 实现中发现并修复的问题（12 个，全部有本机证据）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| ① | 缺 `cryptography` 连不上 MySQL | MySQL 8 默认 `caching_sha2_password` 非 TLS 连接需要它 | 补依赖（M0 已发现，M1 确认必需） |
| ② | **未声明的 state key 被 LangGraph 静默丢弃** | 图只保留 schema 中声明的键 → `above_threshold` 丢失 → E13 走错分支（表现为"全都不达标"） | 派生标志全部显式声明于 `CSState` 并加注释 |
| ③ | 台账解析把文件头当条目 | `version/updated_at` 被当作子场景，`status` 为空报错 | 解析器只在进入列表后收集键值 |
| ④ | 台账 `target` 超 `VARCHAR(32)` | 把落地描述写进了里程碑号字段（建模错误） | `target` 只留 `M5-x`，描述移入 `note` |
| ⑤ | `/internal/*` 被 JWT 中间件拦成 401 | Fiber 的 `Group("/")` 中间件影响其后注册的所有路由 | 内网组注册在 `authGroup` **之前**（并写明为何不能调序） |
| ⑥ | 内网调用被系统代理劫持返回 502 | `httpx`/OpenAI SDK 默认读 `HTTP_PROXY`，localhost 也走代理 | `trust_env=False` + 自建 `http_client`（企业内网通用坑） |
| ⑦ | 字面替身模式"全部低于阈值" | 用 **RRF 融合分**（0.01~0.05）去比 BM25 门槛（3.0），量纲都不对 | 单独记录 BM25 原始分用于字面模式判定 |
| ⑧ | 网关流式只吐第一个 chunk 就"生成中断" | 流式写入发生在 handler 返回后，**fasthttp 的 `RequestCtx` 已被回收**，由它派生的 ctx 立刻 Done | 流式 writer 内使用独立 `context.Background()` |
| ⑨ | langchain 报 `No generation chunks were returned` | 网关流式输出漏了 SSE 的 **`data: ` 前缀**，OpenAI SDK 解析不到任何 chunk | 输出标准 SSE 帧（`data: ` + 空行结尾） |
| ⑩ | 文档变短后 **派生索引漂移** | `kb-sync` 裁剪 MySQL 多余 chunk 时没同步删 Qdrant 点 | 裁剪前取出 id，同步 `DeleteByChunkIDs` |
| ⑪ | 「投诉渠道是什么」被误判为投诉行为而转人工 | 前置意图只匹配"投诉"二字，把**信息类提问**一起吞了 | 增加例外：与"渠道/电话/怎么/多久…"同现时判为信息类 → 走分类检索 |
| ⑫ | 边界违规只加声明、留着"点击入口" | 用户仍会去找一个不存在的入口 = 没拦住 | 违规时**确定性剥除**含操作性措辞的句子（不额外调 LLM） |

> ②⑥⑧⑨ 四个是**同类系统的通用坑**（状态 schema、代理、Fiber 流式、SSE 帧格式），已写进代码注释与技能，避免二次踩。

## 5. 复跑方式

```bash
# 1) 基础设施
docker compose up -d mysql redis && docker start qdrant-m0

# 2) 环境变量（当前不写进 app.env，避免密钥入库；M4 统一治理）
export INTERNAL_KEY=dev-internal-key QDRANT_URL=http://127.0.0.1:16333 \
       QDRANT_COLLECTION=kb_dev EMBEDDING_PROVIDER=fake LLM_PROVIDER=mock LLM_MOCK_OPERATIONAL=1

# 3) 迁移 + Go 服务
go run main.go

# 4) 入库
go run ./cmd/kb-sync --kb ./kb          # 再跑一次可验证断点续跑

# 5) 编排层
cd orchestrator && GO_BASE_URL=http://127.0.0.1:8080 INTERNAL_KEY=dev-internal-key \
  uv run uvicorn app.main:create_app --factory --port 8001

# 6) 验收 + 单测
uv run pytest -q
uv run python tests/e2e/acceptance.py
go test ./internal/ai/...
```
